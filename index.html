START / 2台で対戦

相手の操作を、受け取ろう。

自分の機体を動かす。相手の画面にも届く。
メッシュを使う対戦シューティング。

最初に、AとBを決めよう

Aのスターター ↓Bのスターター ↓
  1. 2人でA・Bを決め、それぞれ自分のスターターを保存。
  2. スモウルビーを開く ↗。
  3. 左上の ファイル → コンピューターから読み込む。
  4. 自分の A_スターター.sb3 または B_スターター.sb3 を選んで開く。

移動・発射・当たり判定は用意済みです。受信する5か所を組み立てると、相手の情報で動くようになります。

この教材について

動画のクライアント／サーバの考え方を参考にした、2台のクライアントで遊ぶ別構成です。通信の中継はメッシュのサービスが行います。別の「サーバ作品」は読み込みません。

STEP 1 / 接続

Aがホスト、Bが参加。

  1. 読み込み後、メッシュの接続画面が開いたらその画面を使う。開かなければ、左下の 拡張機能を追加 → メッシュ。追加済みならメッシュの接続ボタンを押す。
  2. 同じクラスの別ペアと混ざらないように、ペア専用の ドメイン を2人で同じにする。例はそのまま使わず、教員が日付・ペア番号・ランダムな文字を組み合わせて指定する。
  3. A側は メッシュのホストになる（グループの作成） を選ぶ。
  4. A側に表示されたホスト名・グループ名を、Bに伝える。
  5. B側は メッシュに参加する（グループに参加） を選び、Aのグループに参加する。
  6. 接続完了を両方で確認する。まだ緑の旗は押さなくてOK。
接続画面は動画から変わっています。現行画面の「ホストになる」「参加する」を使います。ドメインやグループ名は認証用のパスワードではありません。本名などは送信しません。

✓ A・Bを逆に読み込んでいない？ 同じドメイン・同じグループにつながった？

STEP 2 / 受信の約束

自分の変数と、相手のセンサー。

A側から送る情報

A_x：機体の横位置
A_準備：準備OKなら1
A_ライフ：残りのライフ
A_発射番号：発射の通し番号
A_発射x：撃った横位置

B側から送る情報

B_x：機体の横位置
B_準備：準備OKなら1
B_ライフ：残りのライフ
B_発射番号：発射の通し番号
B_発射x：撃った横位置

全スプライト用の変数はメッシュで共有されます。自分側では変数、相手側では緑色の （○○）センサーの値 で読み取ります。

✓ Aの人は B_ で始まる名前を受信。Bの人は A_ で始まる名前を受信。

数字・マイナス・小数点・英字は半角

正：-130　0.03　A_x ／ 誤：１３０、ー130、Ａ＿ｘ
変数名の「_」も半角です。用意された名前をメニューから選び、勝手に変えません。

x座標＝横 ↔（左側の入力欄）、y座標＝縦 ↕（右側の入力欄）。送る位置は x です。Aは下から上へ、Bは上から下へ撃ちます。

STEP 3 / 2か所

準備と、ライフを受け取る。

  1. 右下の ステージ をクリックする。
  2. 「相手準備」「相手ライフ」を繰り返し設定するプログラムを探す。黄色いコメントも目印。
  3. 左側の メッシュ をクリック。
  4. （　）センサーの値 を作業スペースへドラッグする。
  5. その小さいメニューから、相手の 準備 を選ぶ。
  6. 「相手準備を 0 にする」の 0の入力欄 に、そのブロックを重ねて入れる。
  7. もう一つセンサーブロックを取り、相手の ライフ を選ぶ。「相手ライフを 3 にする」の3へ入れる。
差し込むところAの人が選ぶ名前Bの人が選ぶ名前
相手準備の0B_準備A_準備
相手ライフの3B_ライフA_ライフ

上の図はA用です。Bは表の右列を見よう。接続前はメニューに名前が出ないことがあります。両方の旗を一度押し、少し待ってからメニューを開き直してください。

STEP 4 / 1か所

相手の機体を、相手の位置へ。

  1. 右下のスプライト一覧で 相手 をクリック。
  2. 「ずっと」の中の青い x座標を0にする を探す。
  3. メッシュの （　）センサーの値 を取る。
  4. Aの人は B_x、Bの人は A_x を選ぶ。
  5. 青いブロックの 0 に差し込む。y座標ではありません。

✓ 2人とも旗 → 3秒待つ → 2人ともG。← → で動くと、相手の画面でも機体が動く？ 反映は少し遅れます。

STEP 5 / 2か所

撃ったことと、撃った位置を受け取る。

  1. 右下の 受信ビーム をクリック。
  2. 受信した発射番号を0にする を探す。
  3. メッシュのセンサーで、相手の 発射番号 を選び、0へ入れる。
  4. 受信した発射xを0にする を探す。
  5. 相手の 発射x のセンサーブロックを、その0へ入れる。
差し込むところAの人Bの人
受信した発射番号の0B_発射番号A_発射番号
受信した発射xの0B_発射xA_発射x

ヒント
発射番号は 1 → 2 → 3 … と増えます。前に受け取った番号と比べるので、同じ発射を何度も再生しません。番号が進んだら、そのときの横位置からビームをつくります。

「緑の旗が押されたとき」「クローンされたとき」は先頭です。上には別のブロックをつなげません。今回は、その下にある入力欄だけを変えます。

PLAY / 動作確認

両方の画面で、確かめよう。

  1. 両方とも赤い停止ボタンを押す。
  2. 両方とも緑の旗を押す。ライフが3になる。
  3. 3秒ほど待つ。2人ともキーボードを半角英数にして G を押す。
  4. ← → で移動。スペースで撃つ。連射は2秒間隔。
  5. 相手のビームに当たると、自分のライフが1減る。
  6. どちらかのライフが0になると終了。相手の画面に届くまでは少し時間がかかる。
通信に合わせたゲームです

現行メッシュは約1秒ごとの更新です。ビームはゆっくり進み、相手の発射も遅れて見えます。自分の画面の「受信ビーム」が自分に当たったときだけ、自分のライフを減らします。両画面の映像が完全に一致する競技用の仕組みではありません。

同じ瞬間に当たると両者0になることもあります。再戦は必ず2人とも停止→旗→3秒待つ→G。片方だけ旗を押すと、前の情報と混ざります。

✓ 位置が届く／発射が届く／双方のライフが減る／0で終了／再戦できる、をペアでチェック。

HELP / つまずいたら

5か所を、順に見直す。

症状確認すること
動き始めない接続済み？ AとBを読み込んだ？ 2人ともG？ ステージの相手準備は正しい名前？
相手が中央のまま「相手」のx座標に相手の _x センサーを入れた？
自分の弾だけ見える相手側の「受信ビーム」の発射番号・発射xを見直す。
センサー名が出ない接続・相手の旗を確認して数秒待つ。メニューを閉じて開き直す。
入力しても動かないステージを一度クリック。キーボードを半角英数にする。
切断・大きく遅延する対戦を止め、接続し直す。次の発射へ飛ぶ場合もあるため、撃つ間隔を広げる。

学校の回線で通信できない場合は、HTTPS／WebSocketの graphql.api.smalruby.app（443） への通信を管理担当者に確認してください。

REFERENCE / 教員用

完成見本・授業の見通し。

Aの完成見本 ↓Bの完成見本 ↓

完成見本との差は、受信用センサーブロック5個だけです。スターターの移動・初期化・ビーム処理を途中で変える必要はありません。

目安学習内容
0〜10分A/Bの確認・読み込み・メッシュ接続
10〜20分準備・ライフの受信
20〜30分位置を受信して相手を動かす
30〜40分発射番号と位置を受信、対戦
40〜50分改良と振り返り：何を送り、何を受け取り、どんな処理に使ったか

速く進む生徒は、ビーム速度や発射間隔を変え、通信の遅れと遊びやすさの関係を調べよう。「相手も楽しめる」工夫をペアで相談しよう。

検証範囲：ファイル構造・5か所の差分・受信処理は自動検査対象です。学校回線での2台通信は授業前に完成見本で確認してください。
